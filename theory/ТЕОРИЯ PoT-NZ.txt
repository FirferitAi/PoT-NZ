ТЕОРИЯ PoT-NZ
POWER-OF-TWO QUANTIZATION WITHOUT ZERO
(квантование с шагом-степенью двойки и пропуском нуля)
================================================================

Версия 2. Дополнена результатами экспериментов (раздел 9) и уточнёнными
порогами (разделы 7-8). Исходная формулировка: «ТЕОРИЯ ШАГА С ПРОПУСКОМ НУЛЯ».

Проект-реализация: D:\AI\Мой Ai\Power-of-Two Quantization without Zero (PoT-NZ)
Код: src/quant.py (квантователь), src/pack.py (упаковка), src/model.py (QAT-модель).


0. КРАТКО
----------------------------------------------------------------
Сетка квантования: значения w = (n / 2^p) * k, где
    k ∈ {-2^p, ..., -1, 1, ..., 2^p},   ноль ОТСУТСТВУЕТ.
Всего значений 2^(p+1)  ->  ровно p+1 бит на код, все коды заняты.
Шаг — двоичная дробь n/2^p, поэтому представление точное: нет 1/3, 1/5, 1/6.
Обучение идёт с квантованием на каждом шаге (QAT, STE); за счёт этого
готовые веса всегда лежат ровно на сетке.

Заявленные преимущества:
  1) p+1 бит вместо p+2 у сетки с нулём — нет «мёртвого» кода нуля;
  2) нет проблемы «вес близок к нулю, но не ноль» — нуля в сетке нет;
  3) простая арифметика: де-квантование = умножение на степень двойки
     (сдвиг) и на масштаб блока, без zero-point;
  4) точное восстановление кода (нет накопления ошибки округления).

Цена: между k = -1 и k = +1 шаг вдвое больше (n/2^(p-1)), а ровно ноль
непредставим.


1. ОСНОВА: СЕТКА
----------------------------------------------------------------
Диапазон: [-n, +n], n — полудиапазон.
Шаг:      step = n / 2^p,   p — целое >= 1.
Значения: w = step * k,  k ∈ {-2^p, ..., -1, 1, ..., 2^p}.
Всего:    2^(p+1) значений.

Пример: n = 1, p = 4
    step  = 1/16
    k     = -16..-1, 1..16
    всего = 32 значения = 5 бит

Важно: m = 2^p — именно степень двойки. Иначе (например, m = 3) появляются
шаги 1/3, 1/6, теряется двоичная точность и симметрия.


2. КОДИРОВАНИЕ В p+1 БИТ
----------------------------------------------------------------
Прямое отображение k -> c (теория, раздел 4):
    c = k + 2^p       при k < 0
    c = k + 2^p - 1   при k > 0
Обратное:
    k = c - 2^p       при c <= 2^p - 1
    k = c - 2^p + 1   при c >= 2^p

Пример p = 4 (5 бит):
    k = -16 -> c = 0
    k = -1  -> c = 15
    k = +1  -> c = 16
    k = +16 -> c = 31

Все 32 кода используются; код нуля отсутствует (его и нет в сетке).
Проверено кодом: src/quant.py (encode_k / decode_c), тест
tests/test_quant.py::TestCodec — все коды заняты, roundtrip точный.


3. СВОЙСТВА СЕТКИ
----------------------------------------------------------------
- Симметрична относительно нуля.
- Шаг n/2^p везде, КРОМЕ перехода через ноль: между k = -1 и k = +1
  шаг равен 2n/2^p = n/2^(p-1).
- Ноль не входит: диапазон [-n, -n/2^p] ∪ [+n/2^p, +n].
- Переход через ноль — штатная ситуация, отдельного кода не требует:
  шаг просто удваивается один раз.
- Абсолютная ошибка квантования <= step/2 и падает вдвое с каждым битом.
- Относительная ошибка sum|q-w|/sum|w| на практике тоже падает примерно
  вдвое на бит (см. раздел 9.2).


4. ПОЧЕМУ НЕТ ЧИСЕЛ ТИПА 1/3
----------------------------------------------------------------
Все значения кратны n/2^p, то есть являются двоичными дробями с конечной
записью. Плюсы:
  - точное представление в двоичной системе;
  - нет ошибок округления при кодировании/декодировании (проверено побитово:
    16/16 слоёв, max|ошибка| = 0 при fp32-масштабах);
  - простая арифметика: сдвиги вместо деления.
Для сравнения: int8 с шагом absmax/127 даёт десятичную дробь, двоичная запись
которой бесконечна, поэтому восстановление веса всегда с округлением.


5. МАСШТАБ НА БЛОК
----------------------------------------------------------------
Реальные веса не ограничены [-n, n], поэтому вводится масштаб блока:

    w = s * (n / 2^p) * k,    s = absmax(блок) / n

Блок — 32 веса (гиперпараметр block_size). Накладные расходы:
    масштаб fp16: 16 бит / 32 веса = 0.5 бита на вес
    итого на вес: (p+1) + 0.5 бита

Если писать все веса в шкале n = 1 без масштаба (global-режим), сетка
фиксирована в [-1, 1]; инициализация весов ~N(0, 0.02) тогда «подтягивается»
квантователем к ±1/2^p — это меняет эффективный масштаб обучения
(наблюдение: такой режим быстрее сходится на коротких прогонах).


6. QAT И STE
----------------------------------------------------------------
Обучение идёт с квантованием в прямом проходе:
    q = clamp-округление(w) на сетку
    forward:  w + (q - w).detach()     (STE, градиент проходит насквозь)

Следствия:
  - проблем «вес близок к нулю, но не ноль» нет: сетка не имеет нуля, а
    QAT учитывает ошибку округления ещё в обучении;
  - память при обучении не экономится (нужны fp32-копии для градиентов),
    но готовая модель компактна;
  - в модели C доля весов ровно на сетке — 100%, доля нулей — 0%.


7. СРАВНЕНИЕ ВАРИАНТОВ И ПОРОГИ
----------------------------------------------------------------
Вариант A (PoT-NZ): сетка без нуля, 2^(p+1) значений, p+1 бит.
Вариант B: сетка с нулём, 2^(p+1)+1 значений; плотно требует ceil(log2(...))
    = p+2 бит (33 значения не влезают в 5 бит при p = 4).
Вариант B с вырезанием нуля (SZM1): 1 бит маски + (p+1) бит на ненулевые.

Пороги (доля точных нулей f):

  B(вырезание) vs A, коды перенумерованы в p+1 бит:
      1 + (p+1)(1-f) < p+1   =>   f > p/(p+1)
      p=2: 66.7%   p=3: 75%   p=4: 80%   ...  (при сравнении с p+1)
      ВАЖНО: это сравнение «код в код». Ниже — сравнение с реальной 5-битной
      сеткой (p=4), которое и используется на практике:
      1 + 5(1-f) < 5        =>   f > 20%
      1 + 8(1-f) < 5 (p=7)  =>   f > 50%

  B(вырезание) vs плотный B (p+2 бита на код, без перенумерации):
      f > 1/6 = 16.7%  — отсюда «порог 17%» в первой версии теории.

  B(плотный, p+2 бита) vs A (p+1 бит):
      p+2 > p+1 всегда, то есть A всегда меньше при равном p.

Практический вывод: если ноль не даёт заметной доли (f < 20% при 5-битной
сетке), вырезать его невыгодно — дешевле «просто 5 бит» (вариант A).
Проверено на реальных файлах: при f = 5.83% разреженный вариант B на 9.96%
больше 5-битной A (777 600 против 707 183 байт).


8. УПАКОВКА: SZP1 И SZM1
----------------------------------------------------------------
SZP1 (плотный, вариант A/B): коды p+1 бит подряд, без выравнивания на байт;
8 кодов по 5 бит = ровно 5 байт. Формат:
    "SZP1" | uint32 (длина JSON) | JSON | коды + масштабы fp16 + fp32-прочее

SZM1 (маска нулей, вариант B):
    "SZM1" | uint32 (длина JSON) | JSON |
    маска нулей (1 бит на вес) | коды ненулевых (p+1 бит) | масштабы fp16 |
    fp32-прочее

Размер в битах на вес:
    SZP1: (p+1) + 16/block_size
    SZM1: 1 + (p+1)(1-f) + 16/block_size

Сжатие относительно fp32:
    compression = 32 * (q + e) / (q * bits + 32 * e)
    q — число квантуемых параметров, e — число fp32-параметров
    (эмбеддинг, lm_head, LayerNorm, bias).

Из формулы видно главное: сжатие определяется отношением q/(q+e), а не
абсолютным размером модели. У маленькой char-модели (q = 786k, e = 40k)
получается 4.67×, у средней BPE-модели с эмбеддингом 16k (q = 3.1M, e = 4.1M) —
всего 1.56×, а если квантовать и эмбеддинг (e -> 33k) — 5.64×.


9. ЧТО ПОКАЗАЛИ ЭКСПЕРИМЕНТЫ
----------------------------------------------------------------
9.1 Качество vs битность (char-модель 826k, tiny-shakespeare, 60 эпох)
    fp32: 6.05
    p=4 (5 бит): 5.96    p=5 (6): 5.96    p=6 (7): 5.93
    p=7 (8): 5.96        p=8 (9): 5.95
    -> потолок fp32 достигается уже на p = 4 (5 бит); дальнейшие биты
       качества не добавляют, только размер.

    Агрессивный край (30 эпох, база 8.02):
    p=2 (3 бита): 7.79   p=3 (4 бита): 8.01   p=4: 7.82
    -> даже 8 значений сетки не ломают обучение.

9.2 Клип и точность
    Клип (доля весов на границе |k| = 2^p) держится на 3.1-3.6% при любом p.
    Это структурный минимум: масштаб блока = absmax, поэтому максимальный
    вес блока всегда лежит на границе сетки (1/32 = 3.125%). Это не потеря
    качества.

    Настоящая точность — относительная ошибка sum|q-w|/sum|w|:
    p=2: 27.1%  p=3: 11.4%  p=4: 5.08%  p=5: 2.45%
    p=6: 1.18%  p=7: 0.58%  p=8: 0.29%
    -> ровно x0.5 на каждый бит, как и предсказывает теория.

9.3 Сравнение с int8 (та же архитектура)
    int8 (PTQ, масштаб на блок 32): ppl 6.052, 8.5 бита/вес, 995 328 байт
    int8 (PTQ, масштаб на тензор):  ppl 6.055, 8.0 бита/вес, 946 180 байт
    PoT-NZ p=7 (8 бит, QAT):         ppl 5.96,  8.5 бита/вес, 1 002 098 байт
    PoT-NZ p=6 (7 бит, QAT):         ppl 5.93,  7.5 бита/вес,   903 793 байт

    -> на 7.5 битах PoT-NZ догоняет int8 на 8.5 битах, файл на 9% меньше.
       Причины: заняты все 2^(p+1) кодов (у int8 ноль — «мёртвый» код и
       отдельный zero-point), шаг двоичный (одно умножение вместо деления).

9.4 Квантование эмбеддинга (средняя модель 7.29M, BPE 16k)
    A fp32:                ppl 258.8,  .bin 29 158 216, 1.00x
    C p=4 (эмбеддинг fp32): ppl 254.8, .bin 18 739 941, 1.56x
    C p=7 (эмбеддинг fp32): ppl 235.4, .bin 19 919 619, 1.46x
    C p=7 + эмбеддинг:      ppl 241.1, .bin  7 887 735, 3.70x
    C p=4 + эмбеддинг:      ppl 239.3, .bin  5 172 084, 5.64x

    Квантование эмбеддинга и lm_head (QuantEmbedding + QuantHead) — главный
    источник сжатия: 5.64x вместо 1.56x при качестве не хуже fp32.
    max|w| эмбеддинга после QAT 0.342-0.367 — в [-1, 1], клип 3.2-3.8%
    (тот же структурный absmax).

9.5 L1 и разреженность (char-модель, вариант B, 60 эпох)
    loss = CE + lambda * sum|w| на квантуемые веса.

    p=7 (8 бит):  lambda 0 -> 0.73% нулей, ppl 4.79
                  lambda 5e-5 -> 36.1% нулей, ppl 6.29, SZM1 817 568 байт
                  (это всё равно +16% к 5-битной A — маска не окупается)

    p=4 (5 бит):  lambda 0 -> 5.91% нулей, ppl 4.79, SZM1 777 243 (+9.9%)
                  lambda 1e-5 -> 18.4% нулей, ppl 4.99, SZM1 715 778 (+1.2%)
                  lambda 2e-5 -> 32.0% нулей, ppl 5.25, SZM1 648 968 (-8.2%)
                  lambda 3e-5 -> 39.3% нулей, ppl 5.66, SZM1 612 948 (-13.3%)
                  lambda 5e-5 -> 43.6% нулей, ppl 6.20, SZM1 591 802 (-16.3%)

    -> SZM1 окупается начиная с f ~ 20% (при p=4), рабочая точка lambda = 2e-5:
       32% нулей, файл на 8.2% меньше плотной 5-битной A, ppl +9.4%.
    -> при p = 7 маска невыгодна в принципе (нужно f > 50%).

    Почему доля нулей не монотонна по lambda: масштаб блока = absmax, L1
    сжимает блок целиком, absmax падает вместе с весами, шаг сетки
    уменьшается — окно нуля |w| < step/2 остаётся узким. Ноль появляется
    только при «относительном» разреживании внутри блока.


10. РЕКОМЕНДУЕМЫЕ КОНФИГУРАЦИИ
----------------------------------------------------------------
Маленькая char-модель (826k):
    n = 1, p = 4, skip_zero = true, scale_mode = per_block, block_size = 32
    -> 5.5 бита/вес, 4.67x, ppl не хуже fp32 (5.96 против 6.05 при старом
       запуске; 4.80 против 4.80 при исправленной инициализации эмбеддинга).

Средняя модель (7.29M, BPE 16k, tie_embeddings):
    n = 1, p = 4, skip_zero = true, per_block/32, quantize_embedding = true
    -> 5.64x (5.17 МБ против 29.16 МБ), ppl 239 против 259 у fp32.

Если нужна разреженность (только p <= 4):
    вариант B + L1 (lambda = 2e-5) + формат SZM1
    -> 32% нулей, -8.2% к размеру, ppl +9.4%.

Чего не делать:
    - не вырезать ноль при p >= 6 (маска не окупается);
    - не включать L1 без грубой сетки;
    - не квантовать эмбеддинг «за компанию» без проверки: у него свой
      диапазон, который поглощается per-block масштабом, но при n=1 global
      режиме это меняет динамику обучения.

12. ОБОЗНАЧЕНИЯ
----------------------------------------------------------------
n          полудиапазон сетки
p          степень двойки; шаг = n/2^p
k          целый индекс на сетке (без нуля)
c          код k в p+1 бит
s          масштаб блока (absmax блока / n)
q          число квантуемых параметров
e          число fp32-параметров
f          доля точных нулей (для варианта B)
SZP1       плотный бинарный формат (коды p+1 бит)
SZM1       формат с битовой маской нулей
STE        straight-through estimator
QAT        quantization-aware training
